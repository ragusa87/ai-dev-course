### Fonction LOSS => Réduire l'indicateur d'erreur
Dans le cas d'une sortie SoftMax on a un vecteur de probabilité avec l'encodage de l'étiquette ONE-HOT
[0.02, 0.9, 0.03 , ...] => [0, 1, 0] => Perfect match
[0.02, 0.9, 0.03 , ...] => [1, 0, 0] => Mismatch
=> LOSS => -1 * Somme(Y_label * log(Y_model))

### Descente de gradient
-> Calcul des nouveaux poids. On déplace le poids vers une direction qui mêne à au minimum, le "pas" du déplacement va changer durant l'entraînement.
-> On va plus vite au début avec un grand pas, et ensuite on affine.
-> On monitor si le pas change -> Si on bouge plus, c'est que l'entraînement est fini.
-> GRID SEARCH: Pleins d'entrainements avec différents paramètres en parallèle, et on monitor le plus efficace.

### Metric Accuracy
- Les bonnes réponses divisée par les mauvaises.
- 1/N * Somme(1 si max(y_model) == max(y_label) sinon 0)

### Jeux de données
-> TRAIN + VALIDATE + TEST
* Entaîne avec TRAIN, test le résultat avec VALIDATE pendant l'entrainement, Quand l'entrainement est fini on vérifie via TEST
* Eviter l'overfit.

- train (entraînement) — le modèle apprend dessus, ses poids sont modifiés.
- validation (aussi appelé dev set) — sert pendant l'entraînement, pour surveiller l'overfitting et régler les hyperparamètres (nombre de couches, - - taux d'apprentissage, early stopping…). Le modèle ne s'entraîne pas dessus, mais toi tu prends des décisions en le regardant.
- test — touché une seule fois, tout à la fin, pour estimer la performance réelle. C'est ton « verify ».
